# 18. M7 の設計: microSD とファイル

M7 の目標: **アプリがファイルを読み書きできる**。microSD のカードをカーネルがセクタ単位で扱い、FAT は U モードのサービスが扱う。

調査: [research/m7-sdcard.md](research/m7-sdcard.md)（ピン、電源、SDMMC ホスト、クロック、コマンド、IDMAC、キャッシュ、ファイルシステムの候補）。レジスタの値と出典はそちら。

## 1. 前提（調査から）
- ピンは CLK=GPIO43、CMD=GPIO44、D0〜D3=GPIO39〜42 の 4 ビット。IO_MUX の機能 0 に固定（GPIO マトリクスを通らない）。外付けのプルアップがある。
- **カードの電源は SOC_3.3V に直結で、切り替えられない**。VO1（フラッシュ）にも IO エクスパンダ #2 にも関係しない。M5Stack の BSP が入れている LDO VO4 は、Tab5 の回路図では使われていないので触らない。
- カードの抜き差しの検出はない（Detect は未接続）。
- 電源を切れないので、カードを 1.8V に切り替える CMD11 は**決して送らない**（戻すには電源を切るしかない）。3.3V の Default Speed（25MHz）と High Speed（50MHz）だけを使う。
- SDMMC のクロック源は PLL_F160M（SPLL 系）で、PSRAM の MPLL とは独立。

## 2. 段階
| 段階 | 内容 | 実機で確かめること |
|---|---|---|
| M7a | SDMMC ホストの初期化、カードの初期化（400kHz、1 ビット）、**セクタ 0 の読み出し**（まず FIFO のポーリング、だめなら IDMAC）。制御コマンド `sdinfo`（CID/CSD/容量）と `sdread LBA`（16 進のダンプをイベントで） | カードの種類と容量が出る。セクタ 0 の末尾が 0x55AA で、パーティション表が読める |
| M7b | 4 ビット、20→40MHz、IDMAC での複数セクタの読み書き。カーネルのオブジェクト `sd`（セクタ単位） | 速度の測定。**書き込みは試験用の領域だけ**（§4） |
| M7c | U モードのファイルサービス `fs`（`embedded-sdmmc` 0.10、FAT16/32）。ほかのアプリはチャネル `chan:fs` で open/read/write/list を頼む | アプリがファイルを作って読み戻す |

## 3. カーネルの `sd` オブジェクト（M7b、ABI 0.8）
- `open("sd")`（Permissions に `sd`）。持てるのは同時に 1 つ（ファイルサービスだけに許す想定）。
- `ctl(INFO)` → セクタ数（下位 32 ビット。SDXC の 2TB まで足りる）。`ctl(SEEK, lba)`。
- `read`/`write` は 512 バイトの倍数で、今の位置から読み書きし、位置を進める。1 回に最大 4KiB（カーネルの中の、64 バイト境界にそろえたバッファを通す。キャッシュの書き戻しと無効化はカーネルが行う）。
- 待たせ方: まずはカーネルが転送の終わりをその場で待つ（4KiB を 40MHz・4 ビットで約 0.2ms＋カードの遅延）。カードの書き込みの busy が長いとき（数十〜数百 ms）は、プロセスを待ち状態にして、スケジューラのループで終わりを見る（`wait` と同じ形）。

## 4. 安全の約束
- **カードの中身は利用者のもの**。M7a は読むだけ。M7b の書き込みの試験は、利用者が試験に使ってよいと言ったカードか、カードの上の決めた場所（たとえば FAT の中の試験用のファイルの領域、または最後のパーティションの外の未使用の末尾）だけにする。どちらにするかは実装の前に利用者に確認する。
- VO1、VO4、IO エクスパンダ #2 には触れない。
- カードがない・応答しないときは、`sd.absent` を出して先へ進む（自己試験の合否に入れない）。

## 5. ファイルサービス（M7c）
- `embedded-sdmmc`: no_std、alloc なし、FAT16/32。作れるファイル名は 8.3 だけ（長い名前は読めるが作れない）。exFAT は読めない（32GB を超えるカードは FAT32 に初期化し直す必要がある）。`fatfs` は no_std に古い nightly の `core_io` が要るので使わない。
- サービスは `sd` を開き、`embedded-sdmmc` の `BlockDevice` を `sd` の read/write で実装する。ほかのアプリとの間は `chan:fs`。メッセージ 256 バイトの中に、要求（op、ハンドル、長さ、名前）とデータ（最大約 240 バイト）を入れる。大きいデータは遅い（後で共有メモリにする）。
- 自動起動（flags の autostart）で起動しておく。

## 6. 試験
- t5emu: SDMMC ホストとカードの最小のモデル（コマンドへの応答、512 バイトのセクタを持つ小さいディスクイメージ。`--sd FILE` で与える）。カーネルの初期化の手順とセクタの読み書き、ファイルサービスを試す。
- QEMU（virt）: `sd` は `NoDevice`。
- 実機: §2 の各段階。
