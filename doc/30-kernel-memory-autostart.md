# 30. カーネルの RAM の拡張、プロセス 8 個、起動時の自動起動

doc/28 の結果（カーネルの区画が 99%、プロセスの上限が 4）を受けた作業。利用者の判断（2026-11-01）: カーネルが L2MEM 上側を使えるようにし、プロセスの上限を 8 にしてから、自動起動を入れる。

## 1. 区切りと状態
| 内容 | 状態 |
|---|---|
| カーネルの .bss を L2MEM 上側（RAM_HI）へ、スタックを 128 KiB に | QEMU、t5emu、実機で確認 |
| XIP のスロットの対応付けをスロットの先頭アドレスに基づく形に | t5emu の自己試験（hello-xip、xipcheck）で確認 |
| プロセスの上限 8 | QEMU、t5emu、実機で確認 |
| 自動起動（`wifi`、`fs`、`net`、`netctl`）と SD の規則ファイル | 実機で確認（§5） |

## 2. カーネルの RAM（`kernel/link-esp32p4v1.ld`、`kernel-common.ld`）
| 区画 | 範囲 | 中身 |
|---|---|---|
| RAM | 0x4FF0_0000〜（164 KiB） | .ram_text、.data、スタック（128 KiB） |
| RAM_HI（新） | 0x4FF4_0000〜（256 KiB） | .bss（113 KiB。残りは空き） |
| APP_POOL | 0x4FF8_0000〜0x4FFA_0000（128 KiB） | PSRAM がないときのアプリの置き場（以前は 384 KiB） |

- RAM_HI には、ブートローダが何もロードしない。.bss はロードされない区画（NOLOAD）で、カーネルが起動時に 0 にする。
- PMP は、どのエントリにも当たらない U モードのアクセスを拒否する（doc/07 §3）。RAM_HI にはどのプロセスにもエントリを与えないので、保護の設定は変えていない。自己試験の `fault/load-kernel-ram` と `fault/store-kernel-ram` は、`.bss` の印に触って拒否されることを確かめている（`.bss` は RAM_HI に移った）。
- スタックの大きさは、プラットフォームのリンカスクリプトで決める（`KERNEL_STACK`）。P4 は 128 KiB、QEMU は 96 KiB（.bss とログが同じ 256 KiB の区画にあるため）。
- **見つかった問題**: プロセスを 8 にすると、スタック上に置いているスケジューラ（プロセスの表を含む）が倍になり、t5emu でカーネルのスタックが溢れた（0x4FF0_0000 より下への書き込みで止まった）。以前は溢れても下の .bss を黙って壊していたはずのところが、.bss を移したので見つかった。実機の起動時の使用量は 45,840 B で、元の 48 KiB に迫っていた。

## 3. XIP のスロット（`map_xip`）
- 以前は、XIP のアプリのテキストを `0x4200_0000 + k × 8 MiB` に、データを PSRAM の物理 `k × 8 MiB` に置いていた（k はスロット番号）。一方で、コピー方式のスロット k の先頭は「プール（24 MiB）÷ プロセスの数」で決まり、両者が一致していなかった。上限 4 では大きな XIP のアプリがなかったので表に出なかった。
- 今は、スロットの先頭アドレスを基準にする。テキストは `0x4200_0000 +（先頭 − PSRAM の窓）`、データはそのままスロットの中（2 つ目の線形マップ `0x4A00_0000 + 同じ差`）。テキストの窓は 32 MiB（MMU のエントリ 512〜1023）。
- スロットの大きさは、64 KiB（MMU のページ）の倍数にそろえる。プールが小さいとき（PSRAM がない、QEMU）は、従来どおり PMP の粒度（128 B）でそろえる。

## 4. プロセスの上限 8（`sched::MAX_PROCS`）
- PSRAM のアプリのプール 24 MiB を 8 等分し、1 スロット 3 MiB（`net` は約 1.3 MiB）。

## 5. 自動起動（`make apps-auto`、`make install-auto`）
- カーネルは、ストアの中で自動起動の印（`--autostart`）の付いたアプリを、起動時に引数 0、0 で動かす（以前からある仕組み、doc/14）。
- ストアのイメージ（t5emu の試験が使う）では印を付けない。試験の中の `run net 1` などが二重起動になるため。実機に入れる版だけ印を付けて別に作る。
  - 対象: `wifi`、`fs`、`net`、`netctl`（`AUTO_APPS`）
  - 置き場: `build/apps/auto/`
  - インストール: `make install-auto PROBE=...`、または `t5log rtt --cmd "install ..."`
  - 追記（2026-11-02）: `make install-apps PROBE=...` は、ストアのアプリすべてを今のソースから入れ直す（自動起動のものは印つき、`fault` は除く）。実機のストアは最後に入れたものを持ち続け、起動時の自己試験もそれで動くため。次の起動から使われる。
- 起動順に頼らないための変更:
  - `net` は、Wi-Fi のリンクがない間、1 秒ごとに `netdev:wlan0` を開き直す（チップがまだ上がっていなければ `NoDevice`）。MAC を待つのは 2 秒まで。`wifi` を後から起動し直した場合にも効く。
  - `netctl` は、`svc:netctl` と `svc:fs` に、それぞれ最大 10 秒、つながるまで待つ。
- `netctl` の mode 7: 守りの規則（doc/24 §4）を SD の `T5OS/NET.RUL` に書く。起動時の `netctl`（mode 0）がそれを読む。
- 実機の起動（2026-11-01）:

  | 時刻 | できごと |
  |---|---|
  | 2.6 秒 | 4 つが起動 |
  | 4.8 秒 | `net` が `wlan0` を開き（開き直しの 2 回目）、`netctl` が SD の規則（4 つ）を入れて終了 |
  | 18.3 秒 | Wi-Fi が接続 |
  | 25.3 秒 | SLAAC |
  | 26.0 秒 | DHCP |
- 自動起動を外すには、印のない版（`build/apps/*.t5a`）を入れ直す。
