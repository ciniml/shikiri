# 31. CPU 使用率の計測

doc/28 §5 で「測れていない」とした CPU の使用率を、スケジューラで数えて `ps` で出すようにした。

## 1. 数え方（`kernel/src/sched.rs`、`process.rs`、`main.rs`）
- **プロセスの時間**（`Process::cpu`）: `run_slice` の前後の時刻の差を足す。プロセスのシステムコールをカーネルが処理する時間も含む（「user + sys」にあたる）。たとえば `netdev:wlan0` への書き込みでは、SDIO の転送（CMD53）までがそのプロセスの時間になる。
- **待ちの時間**（`Stats::idle_ticks`）: 全員が眠っているときの `wait_for_interrupt`（WFI）の前後の差を足す。
- **カーネルの時間**: 窓の長さ − 待ち − プロセスの合計。スケジューラの回り目の仕事が入る（C6 からの受信、ホストリンク、表示、制御コマンド、プロセスの起動など）。
- 時刻は SYSTIMER（16 MHz）。

## 2. 出し方（`ps`）
`ps` は、前の `ps` からの窓での使用率を千分率（‰）で出し、窓の始まりを今にする。

| イベント | フィールド |
|---|---|
| `proc.info` | 従来のものに加えて `cpu_ms`（起動からの合計）、`cpu_pm`（窓の中の千分率） |
| `kernel.cpu` | `window_ms`、`idle_pm`、`procs_pm`、`kernel_pm`、`idle_total_ms` |

確かめた値:
- t5emu: 回り続ける `spin` が 996‰（窓 2 秒）。
- 実機の値は §3。

## 3. 実機の値（2026-11-01、自動起動の `wifi`、`fs`、`net` が常駐、iotap）
**何もしていないとき**（窓 21.2 秒）:

| | 千分率 |
|---|---|
| 待ち | 992（99.2%） |
| `net` | 2 |
| カーネル | 6 |
| `wifi`、`fs` | 0 |

**Wi-Fi で TCP の echo**（窓 5.4 秒）: LAN の PC から `nettest 1` に 4 MiB を送り、送り返させた（片道 8.07 Mbps、往復で約 16 Mbps、4.16 秒）。

| | 千分率 |
|---|---|
| `net` | 498 |
| カーネル | 196 |
| `nettest` | 29 |
| 待ち | 276 |

- 窓には転送の前後の約 1.2 秒が含まれるので、転送中の使用率は 8 割前後と見られる（推定）。
- `net` の時間には、Wi-Fi のフレームの書き込み（SDIO）と読み出しのシステムコールが入っている。カーネルの時間の大半は、スケジューラの回り目で C6 から受信する SDIO の読み出しと考える（未分解）。
- Wi-Fi の速さを上げるには、SDIO の転送（今は 20 MHz・4 ビット、CPU が待つ）をまとめるか、DMA の完了を待つ間に眠るのが先になりそう（未着手）。

## 4. Wi-Fi の CPU 負荷を下げる（2026-11-01）
利用者の判断で CDC-NCM を後回しにし（doc/research/net-stack.md §1.2）、Wi-Fi の負荷を見た。

- **計測**: SDIO のコマンド（`sd::command_on`）にかかった時間と回数を、スロットごとに数え、`wlan.stats` に `bus_ms`、`bus_cmds` として出すようにした。
- **最初の値**（20 MHz、16 MiB の echo、片道 8.08 Mbps）: コマンドは 1 回あたり平均 95 µs、フレームあたり約 2 回。
- **High Speed（40 MHz）**: カードの CCCR 0x13 の SHS を見て、EHS を立ててから 40 MHz にする（SD カードと同じ手順、`sdio::high_speed`）。切り替え後に C6 のレジスタを 8 回読み、失敗したら 20 MHz に戻す（`wlan.speed`）。
  - 結果: 片道 8.08 → 8.95 Mbps（+11%）、コマンド 1 回あたり 95 → 73 µs。
  - tab5_claude_client では 40 MHz が失敗したとされるが、ここでは High Speed の切り替えをしてから上げたので動いた、と考える。ただし `wlan.speed` のログは起動時の RTT の溢れで失われ、40 MHz になったことは直接は確かめていない（コマンドの速さからの推定）。
- **受信のコマンドを 1 つ減らす**: INT_RAW（0x50）から PACKET_LEN（0x60）までを 1 回の 20 バイトの読み出しで取る。割り込みの印の有無にかかわらず、長さと読んだ量の差でデータの有無を決める（読んだ直後に来たパケットを取りこぼさない）。
  - 結果: 同じ転送でのコマンドの総数が約 25% 減った（72,783 → 54,701）。速さは 8.82 Mbps で変わらない。
- **今の上限は `net` の CPU**: 転送中の窓で `net` 59%、カーネル 20%、待ち 16〜17%。SDIO のバスにかかる時間は全体の 2 割ほどで、残りは `net` の中の処理（smoltcp、フレームのコピー、フィルタ、システムコール）。速さを上げるなら、ここを分解して減らすのが次になる（未着手）。
