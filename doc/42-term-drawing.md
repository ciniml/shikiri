# 42. ターミナルの描画を速くする

利用者の指示（2026-11-03）:「よさそう。すすめて」。doc/41 の報告で次の候補に挙げた、`term` の描画の速さ（判断: 計ってから直す）。

## 1. 計測（実機、CPU 360MHz）
`term` にデバッグのイベント `term.draw`（描いたマス、描く時間、`flush` の時間。大きな描き直しだけ）と、計測のモード（`run term 1`）を足した。

| 何を | 時間 | 備考 |
|---|---|---|
| 画面全体（1760 マス）を描く、1 画素ずつ `put` | 223 ms | 前の版 |
| 同じ、隣り合う画素の向きに描く（§2.1） | 60 ms | |
| フレームバッファ全体（1.8 MB）の `fill` | 31 ms | 書き込みだけで約 59 MB/s |
| フレームバッファの文字の範囲を 1 行（32 画素）ずらす（`copy_within`） | 30 ms | 読み + 書きで約 115 MB/s |
| `flush`（キャッシュの書き戻し、全体） | 0.8〜0.9 ms | |
| ベンチ（100 行、行ごとに描く。画面が埋まると毎行スクロール） | 50.4 ms/行 → **33.2 ms/行** | §2.3 の前と後 |

- フレームバッファは PSRAM にあり、`term` のメモリも PSRAM にある。CPU からの PSRAM の転送はキャッシュ越しで、約 115 MB/s（読み書きの合計）が上限に見える。PSRAM 自体は 200MHz の HEX（DDR）で、ピークはもっと高い（doc/research/m4-psram-and-clock.md）。差の理由（キャッシュの設定、DSI の DMA の読み出しとの競合など）は調べていない（未解決）。
- 向きが 270° のとき、横 1 列の文字はフレームバッファの縦 1 列になる。1 画素ずつ横に描くと、書き込みは 1440 バイトずつ飛ぶ。

## 2. 変更（`user/apps/term/src/main.rs`、`t5_rt::Display`）
### 2.1 隣り合う画素の向きに描く
- `Display` に `index`（公開した）、`steps`（ユーザーの x + 1 と y + 1 でフレームバッファの添字がいくつ変わるか）、`fb_mut` を足した。
- `draw_cell` は、`steps` が ±1 になる軸に沿って、1 回に 32 画素（または 16 画素）続けて書く（`span`）。インクのないマスは `fill` で塗る。

### 2.2 見えているものと同じマスは描かない
- `SHOWN`（マスごとに、最後に描いた `Cell` とカーソルの有無）を持ち、同じなら描かない。最初の `fill` の後の画面は、空白の `SHOWN` と一致する。
- `top` のように画面を消して同じ文字を書き直すと、変わった数字だけを描く。

### 2.3 スクロールはフレームバッファを動かす
- 描き直す行が 12 行以上のとき、`SHOWN` と比べてスクロールを見つける。今の行 r が、`SHOWN` の行 r + k と同じになる k（上下とも）で、同じ行が最も多いものを選ぶ。その場で同じ行の数より 12 行以上多ければ、フレームバッファの文字の範囲と `SHOWN` を k 行ずらし、空いた行は必ず描くようにする（`STALE`）。後は §2.2 で、違うマスだけを描く。
- 12 行は、ずらすのにかかる時間（30 ms）と、1 行の描き直し（約 2.7 ms）から決めた（`MOVE_MIN_ROWS`）。
- パーサにスクロールを記録させず、結果の比較で見つけるので、スクロール領域の中のスクロールや、行の挿入・削除でも、同じ規則で働く。ずらした後は、全部のマスを比べ直す。
- ユーザーの y がフレームバッファで隣り合う向き（90° と 270°、80 x 22 の横置き）のときだけ。0° と 180° は描き直す。

## 3. 試験
- `run term 1`: 100 行のベンチの後に、全部のマスの画素を、マスの内容から求めた色と比べる（`wrong_cells`）。0 なら `term.bench_ok`。
- `make test-p4emu` に `run term 1` を足した（`term.bench_ok` を待つ）。t5emu でも実機でも `wrong_cells=0`。

## 4. 残り
- PSRAM の転送が遅い理由（§1）。
- ハードウェアでの描画: ESP32-P4 の PPA（塗りつぶし、A4/A8 の前景と固定色の合成）や 2D-DMA を使えば、CPU が画素を書かずに済む（推測。カーネルのドライバとオブジェクトが要る）。
- 実際の出力（`cat` など）は、`term` が届いたメッセージをまとめて解析してから 1 回描くので、ベンチ（毎行描く）より速い。
