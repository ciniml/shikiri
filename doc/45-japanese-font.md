# 45. ターミナルの日本語（フォントサービス）

利用者の指示（2026-11-03）:「日本語やりましょう。その後 IPv6 の残り」

## 1. 方針
- `term` の字は 16 x 32 で、全角はその 2 マス、つまり 32 x 32 になる。解析（`vt.rs`）は、もとから全角を 2 マス（`WIDE` と `WIDE_CONT`）として扱っていた。足りなかったのは字形だけ。
- **フォント**:
  - 全角は Noto Sans Mono CJK JP Regular（SIL OFL 1.1、Ubuntu の fonts-noto-cjk にある）を、28 画素の大きさで 32 x 32 に描き、2 値にした。
  - 範囲は、JIS X 0208 の字のうち、East Asian Width が W/F のもの（6649 字）。これに、波ダッシュ（U+301C と U+FF5E）などの揺れのある数字を加えた。
  - 半角カタカナ（63 字）も同じ元から 16 x 32 で描いた。
  - ASCII 以外の半角（ラテン文字、ギリシャ文字、キリル文字、罫線など 836 字）は、すでに使っている Terminus Font の、複数のコンソールフォント（Lat15、Uni2、Uni3、FullGreek、FullCyrSlav）から取った。
  - 使わなかったもの: X11 の `jiskan16`/`jiskan24` は、許諾が「JIS X 9051 から、使用の許可による」という書き方で、再配布の条件がはっきりしない（`/usr/share/doc/xfonts-base/copyright`）。
- **置き場所**:
  - 字形は全部で 0.93 MB ある。`term` に入れると、`term` を入れ直すたびにフラッシュへの書き込みが 30 秒ほどかかる。
  - そこで、フォントを別のアプリ（サービス）`font` にした（判断）。
  - `font` は XIP のアプリで、字形はフラッシュに置いたまま動く。起動時に 1 回だけ共有メモリへ写し、`svc:font` につないだクライアントごとに、その共有メモリを渡す（grant）。
  - 字形は 1 つの共有メモリを全員で見る。ほかのアプリ（後の GUI など）も、同じものを使える。
  - 今の grant は読み書きができる。クライアントが中身を壊すと、ほかのクライアントの字が乱れる（そのクライアント自身の問題にとどまらない）。読み出しだけの grant は今後の課題。

## 2. ファイルの形式（`t5_abi::font`、`tools/mkfont.py`）
- ヘッダ（u32、リトルエンディアン）: `"T5F1"`、半角の数、半角のコードの位置、半角のビットマップの位置、全角の数、全角のコードの位置、全角のビットマップの位置。
- コードは、昇順に並べた Unicode の値（u32）。2 分探索で引く。
- 半角は 32 行の u16（bit15 が左端）。全角は 32 行の u32（bit31 が左端）。
- 作り方: `tools/mkfont.py third_party/jp-font/glyphs.bin`（`--sheet PNG` で見本を描く）。出所とライセンスは `third_party/jp-font/README.md`。どちらの字形も OFL の改変版に当たり、元の名前は使わない。

## 3. 実装
- **`font`**（`user/apps/font`、XIP、`--permit listen:font --permit shm`）:
  - 字形を共有メモリに写してから `svc:font` を開く。先に開くと、写している間（実機で、起動から `svc.listen` まで約 0.4 秒）につないだクライアントが待たされる。最初はこの順で、`term` が待ちきれずに切れた。
  - 受け付けたチャネルに共有メモリ全体を渡し、相手が閉じるまで持つ（8 本まで）。
  - 実機では、署名の確かめに 0.72 秒かかる（`loader.verified ... verify_us=716493`）。
- **カーネル**:
  - 署名の確かめを 64 KiB ずつに分け、その間にウォッチドッグを叩くようにした（`loader::check_signature`）。
  - 前は一括で確かめていた。0.9 MB の像では、t5emu（40 MHz）でウォッチドッグ（4 秒）が切れた。実機でも 0.7 秒、何もしない時間になっていた。
- **`t5_rt::Font`**:
  - `connect(ms)`: `svc:font` につなぎ、grant を待って写像し、ヘッダを確かめる。
  - `narrow(ch)`、`wide(ch)`: 字形を返す。
- **`term`**（`--permit svc:font` を足した）:
  - 起動時に `font` へつなぐ。つなげなければ、描くときに 2 秒おきにつなぎ直す。つながったら全部を描き直す。
  - `glyph_lines` の引き方:
    - ASCII は、これまでどおり自分の中のフォントから引く。
    - それ以外の半角は `narrow` から引く。
    - 全角は `wide` から引く。先頭のマスに左半分を、続きのマスに右半分を描く。
    - フォントがないとき、またはフォントにない字のときは、これまでの代わりの字を描く（全角は先頭のマスだけ）。
  - `Term::cell_at`: 続きのマス（`WIDE_CONT`）は、先頭の字と色を持った「描くときのマス」として扱う。
    - `SHOWN` との比較、スクロールの検出（`same`）、ベンチの確かめ（`check`）は、どれもこの値で行う。
    - これで、先頭の字が変わったとき（あ → い）に、右半分も描き直される。
  - `init` の組み込みの表を `wifi net netctl font term` にした。SD の `START.CFG` も、`run init 1` で書き直した。

## 4. 試験
- `run term 1` のベンチの最後の 4 行は、混ざった行にした。中身は「日本語の表示：漢字かなカナ。「東京」ｶﾀｶﾅ ─│┌┐ äöü αβγ」を 2 回で、80 桁を越えて折り返し、行の終わりにかかる全角も含む。
- `check` は、全部のマスの画素を、マスとフォントから求めたものと比べる。
- `run term 2` は同じベンチだが、最後に画面を消さない（目で見るため）。
- `make test-p4emu` の `term` のベンチは、先に `run font` を行う。`font.ready`、`term.font`、`term.bench_ok` を待つ。t5emu で `wrong_cells=0 font=true`。
- 実機（2026-11-03）:
  - 再起動で、`init` が `font`（3.78 秒）と `term` を起動した。`font.ready` は 4.21 秒。
  - `run term 2` で `term.font`、`wrong_cells=0 font=true`、18.7 ms/行。

## 5. 残り
- 入力は ASCII だけ（キーボードに日本語入力はない）。表示は、SD のファイル（`cat`）や、ネットワークから来たもの（`nc`、将来の SSH）で使う。
- 第 3、第 4 水準の漢字（JIS X 0213）と、絵文字はない。
- 共有メモリの読み出しだけの grant。
