# 66. 標準入出力の検討（記録のみ）

利用者の問い（2026-11-08）:「そういえば標準入出力の概念はありますか？」「性能面や安全性面での懸念はありますか？」→「とりあえず検討内容の記録だけしておいてください」。実装はしていない。

## 1. 今
- 標準入出力はない。
- アプリの出力は構造化ログ（`event!`、doc/12）だけで、ホストに RTT か USB で届く。画面には出ない。
- 起動（`proc:spawn`、doc/38）が渡すのはアプリの名前と数 2 つだけ。親のハンドルは子に渡らない。
- `shell` と `term` は、`shell` が自分で `svc:tty` につないで話している。
- そのため `shell` の `run` で起動したアプリの出力は端末に出ず、パイプもなく、`more`（doc/62）はファイルしか送れない。

## 2. 案
- 起動のときに、親が作ったチャネルの端を子に渡す。子のハンドル 0 と 1 にする。
- ランタイム（`t5_rt`）の `print!` や `read_line` はそれを使う。渡されていなければ今どおりログに出す。
- `shell` がパイプ（`cmd | more`）、端末への出力、ファイルへの書き出し（`> file`）を組む。

## 3. 性能の懸念
- **メッセージが小さい**: チャネルは 1 通 256 バイト（`chan::MSG_MAX`）、片側 4 通まで（`chan::QUEUE`）。1 字ずつ書くとシステムコールと相手の起床が字の数だけ要る。ランタイムで行単位か 256 バイトまで溜める。文字には十分だが、大きなデータ（大きなファイルを `more` に流すなど）は遅い。要るなら `netdev` のような共有メモリの輪（doc/35）にする。
- **詰まり**: 4 通で `Busy` になる。ランタイムは失敗や捨てではなく待つ。
- **描画が律速**: 出力の多いアプリは `term` の描画に引きずられ、`term` と `shell` を忙しくする。Ctrl-C で止められること。
- **チャネルの数**: 1 本でカーネルのバッファが約 2 KiB（256 × 4 × 2）。全体で 32 本（virt は 16）、アプリは 1 つ 8 本、アプリ全体で 16 本（`kernel/src/channel.rs`）。パイプの段ごとに 1 本使う。内蔵 SRAM の「その他」は約 79 KB（doc/61）しかなく、増やすなら SRAM と相談。大きなパイプラインは向かない。

## 4. 安全性の懸念
- **権限の新しい道**: 親が子にハンドルを渡すと、それは権限を渡すことになる。渡せるのはチャネルの端だけにし（`sd` や `display` などのデバイスは渡さない）、権利も絞る（出力は書くだけ、入力は読むだけ）。
- **端末を直接渡さない**: `shell` の `svc:tty` の接続をそのまま子に渡すと、子は
  - `shell` 宛てのキー（`cfg secret KEY VALUE` で打つ秘密など）を読める。
  - エスケープ列で画面を偽り、DSR などへの端末の返事を入力として送り込ませられる。

  `shell` が新しいチャネルの対を作って中継し、子が終わったら（Ctrl-C でも）中継をやめる形にする。信頼しないアプリの出力を受けるので、`term` の VT の解析をファジングで確かめる。
- **シグナルがない**: Ctrl-C を子に届ける仕組みがない。`shell` が受けて `proc:kill/own`（自分が起動したものだけ、doc/52）で止める。
- **相手が消えたとき**: 親が終わると子の書き込みは失敗する。殺すのではなく、エラーを返す、と決める。
- **ログへの代わりの出力**: stdout が渡されていないときにログへ出すと、出した内容は RTT/USB でホストのログに残る。アプリは秘密を stdout に出さない。
- **渡しの原子性**: 起動は非同期（カーネルのサービスの巡回で行う）。起動に失敗したらハンドルを親に戻し、漏れも二重もないようにする。

## 5. 勧め（決めてはいない）
- 起動のときだけ、チャネルの端だけ、権利を絞って渡す。
- `shell` が中継し（端末は渡さない）、Ctrl-C で子を止める。
- ランタイムで溜め、詰まったら待つ。
- 大きなデータは共有メモリで、stdio とは別にする。
- これで、アプリの出力が端末に出る、`more` へのパイプ、`> file` ができる。性能と安全性のどちらも、作れない理由にはならない見込み。

## 6. 実装するなら（未定）
- ABI: `proc:spawn` の要求に渡すハンドル（最大 2〜3 個、チャネルの端だけ、権利の絞り）を足す（小版を上げる）。
- カーネル: 起動の要求とともにハンドルを預かり、子の表の 0、1（、2）に移す。失敗なら親に戻す。
- `t5_rt`: stdout と stdin、溜める `print!`、`read_line`。
- `shell`: 子ごとにチャネルの対、中継、Ctrl-C で `proc:kill/own`、`|` と `>`。
- 試験: エミュレータで `run hello` の出力が端末に出る、`help | more`、`> file` を SD（doc/64）に。
